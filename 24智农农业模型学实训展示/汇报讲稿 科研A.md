CROPGRO-Strawberry 草莓作物生长模型 汇报讲稿
各位老师、同学 / 各位领导好，今天我给大家汇报的项目是CROPGRO-Strawberry 草莓作物生长模型。这是一款基于经典 DSSAT 框架、用 Python 重构优化的草莓专属生长模拟模型，核心是把作物生理生态机理和计算机加速技术结合起来，为设施农业的精准管理提供科学的决策依据。
一、项目背景与开发基座
首先和大家介绍一下项目的开发背景和底层支撑。
传统的作物模型，比如原版 DSSAT，有两个很突出的痛点：第一是技术门槛高、运行慢，它基于 Fortran 语言开发，代码晦涩，学习成本很高，而且传统架构计算效率低，很难支撑大规模的批量模拟；第二是参数复杂、和实际场景脱节，草莓品种参数多、配置难，模型大多停留在科研层面，很难落地到生产和教学里。
针对这些痛点，我们做了针对性的技术革新：一方面用 Python 语言重写核心逻辑，降低使用门槛，同时引入 Numba JIT 即时编译技术，把运行效率提上来；另一方面做模块化的参数接口，简化品种参数的管理，打通 “科研 - 生产 - 教学” 全链条，让模型的价值最大化。
我们的项目是基于 GitHub 开源仓库itsjameshan/CN-strawberryDSSAT开发优化的，核心代码和研究成果都是开源共享的；整体框架依托的是全球通用的 DSSAT 农业技术转移决策支持系统，保证了基础架构的科学性和权威性；技术栈上我们用 Python 作为核心开发语言，搭配 Numba 即时编译技术加速数值计算，兼顾了开发效率和模拟运行的性能。
二、模型定位与核心特点
接下来和大家说明我们这个模型的定位，以及它的核心特点。
我们的核心定位，是在成熟的 DSSAT 框架之上，针对草莓的生长特性做定制化适配，继承框架严谨的生态过程模拟逻辑，同时精准覆盖草莓从种子萌发、营养生长、开花结果到衰老凋亡的完整生命周期，用每日时间步长驱动模拟，还原生长的动态细节。简单来说，就是做一个适用性强、解释性高的草莓生长数字化模型。
它有四个核心特点：
第一是模块化架构设计。我们把环境因子、光合作用、水分平衡这些关键模块拆解开，模块之间低耦合，方便后续扩展功能、维护迭代，灵活性很强。
第二是多品种参数适配。内置了灵活的品种参数配置接口，像红颜、章姬这些不同的草莓品种，只需要导入对应的遗传参数，就能快速适配不同的模拟需求。
第三是生理机制驱动。我们没有用纯经验统计的黑箱模型，而是基于光合作用、呼吸作用这些核心的生理生态过程搭建模型，每一步计算都有生物学依据，结果可解释、普适性更强。
第四是Numba 加速计算。核心循环算法都用 Numba JIT 技术做了优化，运行效率大幅提升，可以支持长时间序列、多场景的快速批量模拟。
三、整体架构与运行流程
了解了定位和特点，我们来看模型完整的运行流程，整体是 “气象输入→过程耦合→状态反馈” 的闭环逻辑，分为三大环节。
第一个环节是驱动输入，也就是气象数据集。模型以 “天” 为时间步长，输入日最高 / 最低温、相对湿度、风速、太阳总辐射、降水量这些核心气象要素，同时还会衍生计算大气压力、饱和水汽压差这些指标，为作物生长提供完整的环境背景。
第二个环节是核心的过程计算，分为三层：
第一层是环境因子与物候驱动。基于天文公式计算日长，用度日模型累加有效积温，驱动作物从发芽、展叶到开花结果的物候阶段推进；
第二层是物质与能量代谢循环。用 RUE 模型模拟光合固碳，Hargreaves 公式估算蒸腾耗水，再结合 Q10 呼吸模型和土壤水分平衡方程，动态计算水分胁迫下的碳收支；
第三层是生物量分配与器官更新。根据不同物候阶段的分配系数，把净光合产物分配到根、茎、叶、果各个器官，同时更新叶面积指数、果实库强、匍匐茎生长这些状态。
第三个环节是状态输出。模拟结束后，会输出三类核心结果：一是总干物质量和各器官的分配比例；二是 LAI、株高、茎粗这些结构指标的动态变化；三是物候期进程、果实数量、产量潜力这些生产指标。
四、六大核心算法模块
接下来是整个模型最核心的部分 —— 六大算法模块，也是我们模型的核心机理支撑，我逐一给大家介绍。
1. 日长计算模块
这个模块的核心作用，是根据地理位置和时间，通过天文学的球面三角关系计算可照时数，给作物的光周期发育、物候进程和光合作用潜力提供基础依据。
核心公式大家可以看 PPT，先计算太阳赤纬角，再通过纬度和赤纬角计算中间项，最终得到可照时数。我们也做了边界条件处理，比如高纬度的极昼极夜情况，都做了判定和修正，保证计算的严谨性。
2. 热时间计算模块
也就是我们常说的积温计算，它的作用是量化累积每日的有效温度，作为作物发育进程的核心驱动因子，精准模拟每个物候阶段的起始和持续时长。
我们没有用简单的线性度日模型，而是采用了梯形响应函数，引入了草莓生长的三基点温度：基础温度 4℃、最适温度 22℃、上限温度 35℃。在基础温度到最适温度之间，热时间随温度线性增加；超过最适温度后，热时间会线性衰减；超过上限温度或者低于基础温度，有效热时间都为 0，这样更贴合作物高温下的实际生理表现。
3. 光合作用模拟模块
这个模块基于 RUE 辐射利用效率模型，计算单位面积作物每天通过光合作用固定的碳量，也就是碳水化合物的积累量。
我们没有只用单一的辐射参数，而是做了多因子耦合修正：用线性函数计算温度效应，模拟光合酶活性的变化；用对数函数描述 CO₂浓度的增益效应；基于比尔 - 朗伯定律，结合叶面积指数计算冠层光截获率；再乘以品种的 RUE 遗传常数，最终得到总光合量，这样模型对实际环境的适配性更强。
4. 蒸腾作用模拟模块
这个模块用来计算作物的蒸腾耗水量，是土壤水分平衡的关键输入，也是后续水分胁迫诊断、灌溉决策的依据。
我们采用 Hargreaves 估算方法，只需要太阳辐射、昼夜温差和平均温度这些常规气象数据就能计算参考作物蒸散量，特别适合观测资料少的区域；再搭配随叶面积指数动态变化的作物系数 Kc，修正得到作物实际的蒸腾量，兼顾了精度和数据可获得性。
5. 水分胁迫响应模块
它的核心目的是量化土壤水分亏缺对作物生长的抑制程度，输出 0 到 1 之间的胁迫因子，用来修正光合作用的效率。
我们用的是土壤水分平衡法：先计算根区的可用水量，也就是田间持水量减去萎蔫点再乘以根系深度；再计算扣除径流渗漏后的有效降雨；用蒸腾量减去有效降雨得到水分亏缺量；最终用亏缺量和可用水量的比值作为胁迫因子，限制在 0-1 之间。胁迫值越高，代表干旱越严重，对光合的抑制就越强。
6. 维持呼吸消耗模块
这个模块用来量化植物维持细胞活性、基础代谢需要消耗的光合产物，是计算净生物量的关键基础。
我们采用经典的 Q10 温度响应模型，简单来说就是温度每升高 10℃，呼吸速率加倍，参考温度设为 20℃。同时我们区分了不同器官的呼吸系数：叶片代谢最活跃，呼吸系数最高；茎、根、果实的代谢水平依次降低，分器官加权求和得到总维持呼吸，计算更精准。
五、物候发育与生物量分配机制
讲完了核心算法，我们来看作物生长的两个核心规律：物候发育和生物量分配。
1. 物候发育阶段
我们把草莓的完整生命周期划分为 10 个阶段，从萌发、出苗、幼苗期，到营养生长、花芽分化、开花、坐果、果实发育、成熟，最后到衰老。
整个阶段推进的核心驱动因子是累积热时间，也就是我们前面说的度日。当累积的热时间达到预设的阈值，作物就自动进入下一个阶段，同时切换对应的生理过程和生物量分配策略。
这里有两个关键节点：一个是 600 度日，是从营养生长转向生殖生长的临界点；另一个是 1000 度日，是果实完全成熟的阈值，代表果实的糖分、风味都达到了最佳状态。
2. 生物量分配机制
作物每天产生的净生物量不是平均分配的，而是根据物候阶段动态调整，相当于植株的 “资源投资策略”。
在萌发和幼苗期，40% 分配给根、40% 分配给叶，优先打好吸收和光合的基础；到了营养生长和花芽分化期，50% 分配给叶片，快速扩大光合面积；进入坐果和成熟期之后，生物量快速向果实转移，成熟期 80% 的净生物量都会分配给果实，保证产量和品质的形成。
除了基础的器官分配，我们还实现了冠芽、匍匐茎、果实数量的动态更新：冠芽每天按 2% 的速率指数增长，匍匐茎由冠芽产生，果实数量则根据开花期、坐果期的不同系数动态计算，完整还原草莓的生长繁殖规律。
六、模型输入输出与验证体系
接下来和大家介绍模型的输入输出，以及我们做的验证工作，这也是模型可靠性的保障。
1. 输入输出参数
模型的输入分为四类：一是站点基础参数，比如纬度、种植日期；二是土壤理化参数，比如根系深度、田间持水量、萎蔫点；三是作物品种参数，比如三基点温度、RUE、消光系数；四是逐日的气象数据，温光水气风这些要素。
输出也分为四个维度：生物量与形态指标、关键器官数量、核心生长状态、生理过程变量，既可以看最终的产量结果，也可以追踪每一天的生长细节，满足不同的分析需求。
2. 四层验证体系
为了保证模型的准确性，我们搭建了四层验证体系：
第一层是单元测试，基于 unittest 框架对每个独立函数做全覆盖测试，从底层保证计算逻辑正确；
第二层是模块级验证，针对物候、生长这些核心模块做功能验证，确保模块之间协同工作符合预期；
第三层是跨语言对比验证，把我们的 Python 实现和 Fortran 原版 DSSAT 用同样的输入做逐行对比，确保核心计算的一致性；
第四层是多情景检验，我们构建了 12 种标准、高温、干旱等典型情景，全方位检验模型在不同环境下的稳定性。
最终的验证结果也很理想：基础计算、生理过程、环境胁迫的测试全部通过，在 3 组官方标准试验中，我们的模拟结果和原版 DSSAT 的差异几乎为 0，充分验证了算法的准确性。
七、技术实现亮点与优化方向
在技术实现上，我们有三个比较突出的优势：
第一是Numba JIT 加速，核心计算函数都编译成机器码，在保留 Python 代码可读性的同时，实现了接近 C/Fortran 的运行性能；
第二是Dataclass 状态管理，用数据类结构化管理植株的状态变量，类型安全、逻辑清晰，方便后续维护扩展；
第三是Pandas 数据流，输入输出都用 DataFrame 处理，天然支持时间序列分析，也能无缝衔接可视化工具，数据处理很流畅。
当然目前模型还有可以优化的地方，我们也梳理了高优先级的改进方向：比如当前 RUE 辐射利用效率、SLA 比叶面积的参数还有上调空间；目前物候只依赖积温驱动，后续会引入光周期模块；同时积温阈值、土壤水分模型这些细节也会持续迭代完善。
八、应用场景与未来规划
最后和大家介绍一下模型的应用场景和未来的规划。
我们的模型覆盖了三大场景：
第一个是科研应用，可以用来做草莓生长机理研究、环境因子敏感性分析、品种参数校准，为理论研究提供数据支撑；
第二个是生产应用，可以辅助优化种植日期、做精准灌溉管理、预测产量，还能评估气候变化对生产的影响，直接服务农业生产；
第三个是教学应用，可以作为教学工具，直观演示作物模型原理，开展 Python 科学计算的实践教学。
真正实现了从科研到生产再到教学的全链条覆盖，形成了产学研用的闭环。
关于长期的功能规划，我们也分了三个阶段：近期会完善日长驱动物候模块和春化模型，夯实基础；中期会开发氮素循环模块和灌溉管理决策模块，提升生产服务能力；远期会加入病虫害影响模拟、Farquhar 光合模型，最终构建完整的全周期智能决策体系。
九、总结
最后做一个简单的总结：
我们这款 CROPGRO-Strawberry 模型，以六大核心算法为基础，以生理机制为驱动，具备模块化、高效率、高解释性的特点；目前已经完成了核心开发，通过了和原版 DSSAT 的零差异验证，也完成了 12 种情景的模拟分析，明确了优化方向。
后续我们会继续迭代完善模型，让它更好地服务于草莓产业的科研、生产与教学。
