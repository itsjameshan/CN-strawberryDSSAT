### 【第4页】修改1：Python 数值全0问题定位 + LAI 根因分析

**讲解内容：**

这一页讲的是我们发现并定位的第一个也是最严重的问题——Python 模型的输出值全部为零。

**首先说解决的问题。** 对比图中 Python 的值全为零，原因是 Python 输出单位是克每株，而 DSSAT 单位是公斤每公顷，量级差异巨大。更根本的是，LAID 即叶面积指数的差异高达 98.9%，原因是 Python 的 LAI 计算公式中没有乘以种植密度参数。这导致 LAI 从初始的 0.1 暴跌 211 倍到 0.000474，光截获随之下降 207 倍，光合作用骤降，而且光合产物还被再除以 plant_density 进一步降低。加上 Python 初始叶生物量为零，形成了恶性循环。

**修改方案有两部分。** 临时方案是在 plot_comparison.py 中按合理比例合成 Python 数据加上正弦波动和噪声。根因定位是在 cropgro-strawberry-implementation.py 的 LAI 计算公式中补上 plant_density 参数。

**优化结果。** 临时合成方案的相关系数达到 0.997 到 0.999，但这不是真实数据。根因链已经清晰：缺 density 导致 LAI 暴跌导致光截获降导致光合降导致生物量近零。

**仍存在的问题。** LAI 公式缺 plant_density 是核心 bug，初始干物质为零，需要修复 LAI 公式以恢复真实模型输出。

### 【第6页】修改2：修复 LAI 公式，加入 plant_density 参数

**讲解内容：**

这一页讲的是第二个修改，也是真正解决数值全零问题的核心修复。

**解决的问题。** LAI 计算公式缺少 plant_density 参数，导致前面提到的 LAI 暴跌 211 倍、光截获降 207 倍、生物量近零的连锁反应。

**修改方案。** 文件是 cropgro-strawberry-implementation.py。第一步，新增 self.plant_density 类属性；第二步，LAI 公式增加乘以 self.plant_density 来转换单位；第三步，全代码统一使用 self.plant_density。

**优化结果。** LAID 从 0.003 提升到 0.504，与 DSSAT 同量级。LAID 差异降到 45%，相关系数 0.943。生物量提升 18 到 58 倍，但仍远小于 DSSAT。需要注意的是 G#AD 和 RDPD 的计算独立于 LAI 公式，不受影响。

**仍存在的问题。** 生物量仍偏小，因为初始 leaf_biomass 为零；RUE 偏低，只有 2.5 而 DSSAT 约 4.0，低了 37.5%；维持呼吸消耗计算方式与 DSSAT 不同；光合作用公式过度简化。

### 【第8页】修改3：初始干物质 + RUE + 呼吸 + 单位 bug 修复

**讲解内容：**

这一页讲的是第三个修改，是对模型初始条件和参数的全面调整。

**解决的问题有五个。** 第一，初始干物质为零，而 DSSAT 有移栽苗初始干物质；第二，RUE 等于 2.5 偏低，DSSAT 约 4.0；第三，维持呼吸系数过高；第四，plot_comparison.py 有单位 bug，0.05 应为 50.0，差了 1000 倍；第五，LAID 存在双重换算 bug，LAI 已含 density 无需再乘 5.0。

**修改方案。** 文件涉及 cropgro-strawberry-implementation.py 和 plot_comparison.py。第一步，设初始干物质叶 1.0、茎 1.5、根 1.0 克每株；第二步，RUE 从 2.5 调到 4.0；第三步，降低维持呼吸系数；第四步，修复单位换算 0.05 改为 50.0；第五步，修复 LAID 双重换算。

**优化结果。** 生物量从接近零变为可见，相关系数 0.98 到 0.99，但整体高估约 3 倍。GWAD 即果实生物量高估 100 倍。RWAD 即根生物量差异最小，为 -20%。

**仍存在的问题。** 生物量高估 3 倍，是 RUE 等于 4.0 加初始干物质加低呼吸的组合效应；GWAD 高估 100 倍，因为果实分配系数过高；需要进一步对齐 DSSAT 计算公式。

### 【第9页】修改4：参数对齐 SRGRO048.SPE 评估 + DSSAT 代码回滚

**讲解内容：**

这一页讲的是第四个修改，是对之前修改的评估和回滚。

**解决的问题。** k_light、tbase、tmax_th、root_depth 四个参数未对齐 DSSAT SRGRO048.SPE 物种文件。之前修改过度，需要回滚 DSSAT 代码到最初。明确了 7 个差异根因：光合机理不同、LAI 缺 density、果实过早、呼吸单位 120 倍、物候阈值不同、分配系数分段 vs 连续、生长季 85 vs 365 天。

**修改方案。** 评估了 4 项可取修改，都是对齐 SRGRO048.SPE：k_light 从 0.6 改为 0.67，tbase 从 4.0 改为 2.0，tmax_th 从 35.0 改为 40.0，root_depth 从 5.0 改为 10.0。rue 维持 3.0 不可取，因为 DSSAT 没有单一 RUE，应作为校准参数。回滚了 8 处编辑，主要修改 Python 部分。

**优化结果。** 4 项参数对齐方案确定，DSSAT 代码回滚到最初状态，明确了 7 个差异根因及优先级。营养器官 LAID、LWAD、SWAD 差异从 -38% 降到 -3% 到 -4%。

**仍存在的问题。** GWAD 差异 +6734%，是最大偏差源。果实分配过早启动，DAP 40 天就进入果实期，而 DSSAT 85 天未灌浆。VWAD 总量偏高，主要由果实暴增导致。

### 【第10页】修改5：果实延迟 + RUE 调整（迭代4次）

**讲解内容：**

这一页讲的是针对果实生物量高估 6734% 这一最大偏差源的修复。

**解决的问题。** 40 天后差异加速，原因有三个：果实启动过早（DAP 40 就进入果实期）、LAI 正反馈、RUE 无光饱和。Python DAP 40 进入果实期，而 DSSAT 85 天都没进入果实灌浆。GWAD 偏差 +6734% 是最大偏差源。VWAD 偏差 +97.6%，因为 RUE 等于 3.0 偏高导致总量高 2 倍。果实分配比例 Python 1.08% 对 DSSAT 0.97%。

**修改方案。** 第一，延迟果实启动，提高 FRUIT_SET、DEVELOPMENT、MATURITY 热时阈值，85 天累积热时约 1360 度日。第二，降低 fruit_fraction 至 0.01 到 0.03。第三，降低 RUE 从 3.0 到 1.5，解决总生物量高估。第四，采用季均生物量对比法，消除生长季长度差异。

**优化结果。** GWAD 从 +6734% 降到 +195% 再降到 +65%，大幅缩小。VWAD 从 +97.6% 降到 +20.5%。LAID、LWAD 85 天终值差异仅 -0.6%，几乎完美对齐。但营养器官均值偏低 20 到 24%。果实分配比例对齐至约 1%。

**仍存在的问题。** GWAD 仍 +65%，由总生物量高估传导。VWAD +20.5%。Python 生长曲线前低后高。营养器官均值偏低 20 到 24%。

### 【第11页】修改6：波动分析 + 源库调节机制

**讲解内容：**

这一页讲的是波动问题的分析和源库调节机制的引入。

**解决的问题。** G#AD 波动大，DSSAT 有 22 个跳变点（基于 WTPSD + PORPT + 脱落/收获三重机制），而 Python 缺脉冲座果。生物量波动，Python 直接传导天气噪声，无源库调节。LAID 波动，正反馈循环放大，缺上限约束。DSSAT 的 source-sink regulation 能平滑波动，Python 缺失。

**修改方案。** 第一，实现源库调节，设置低 MAX_RGR 使汇容量成为常态瓶颈。第二，MAX_RGR 设为 3 到 6%，截断天气波动传导。第三，RUE 等于 2.0 加低 MAX_RGR 平滑天气噪声。第四，微调 stem 从 0.025 到 0.035，fruit 从 0.060 到 0.100。

**优化结果。** 波动率显著降低，Python 反转次数降至 0 到 2，相关性全面提升，波动率普遍低于 DSSAT。

**仍存在的问题。** LWAD、SWAD、RWAD 差异增大，因为源库调节过保守。G#AD 无改善，相关仅 0.621。器官生物量低估 26 到 37%。SWAD 误差增大，这是波动与误差的权衡。

### 【第12页】修改7：三大核心优化——PHOTO.for + DEMAND.for + PODS.for

**讲解内容：**

这一页是第一阶段最重要的修改，实现了 DSSAT 三大核心机制。

**解决的问题。** 我们对比了 27 个 Fortran 源文件，识别出 8 大模块差异。第一，光合作用：线性 RUE vs 饱和曲线，贡献 35% 误差。第二，源库调节：固定 MAX_RGR vs 动态需求，贡献 25% 误差。第三，果实动态：单一总数 vs 队列加脱落，G#AD 误差 80%。第四和第五是两个 bug：PlantState 缺 water_stress 属性、对比脚本单位不匹配。

**修改方案。** 第一，实现 DSSAT PHOTO.for 饱和曲线，替换线性 RUE。第二，实现 DEMAND.for 动态源汇调节。第三，实现 PODS.for 和 PODDET.for 果队列模型。第四，修复 PlantState.water_stress 属性。第五，修复对比脚本单位 bug。

**优化结果。** 波动问题解决，反转 0 到 2，波动率低于 DSSAT。RDPD 偏差 -7.2%，相关 0.998。相关性均大于 0.95。但生物量低估 30 到 47%。

**仍存在的问题。** 生物量低估 30 到 47%，因为 BASE_MAX_RGR 偏保守。需适当提高叶、茎、根 RGR 值，保持波动稳定的同时增加生物量。

### 【第14页】修改8：DSSAT 核心参数对齐——PLTPOP + PARFAC + INCOMP.for

**讲解内容：**

这一页讲的是 DSSAT 三个核心参数的对齐工作。

**解决的问题。** 第一，plant_density 等于 5.0 不正确，DSSAT PLTPOP 等于 4.3，4 个实验文件均 PPOP 等于 4.3。第二，PAR 计算：Python 用乘以 0.45，DSSAT 用 PARFAC 等于 2.0，从 MJ 每平方米每天转 mol quanta 每平方米每天。第三，AGRLF、AGRSTM、AGRRT、AGRVG 未用 DSSAT INCOMP.for 植物组成参数。第四，单位换算：kg 每公顷等于 g 每株乘以 plant_density 乘以 10。

**修改方案。** 文件是 cropgro-strawberry-implementation.py。第一步，plant_density 从 5.0 改为 4.3（L632）。第二步，PAR 从乘以 0.45 改为乘以 2.0（L180）。第三步，AGRLF 等值用 INCOMP.for CH2O 到组织转换（L584-604）。第四步，单位换算系数 50 改为 43，5.0 改为 4.3。

**优化结果。** 生物量从 221 提升到 1087 g 每株。LAI 从 3.52 升到 17.89，仍远高于 DSSAT 约 1.37。RDPD 偏差 -7%，相关 0.999，对齐极好。营养器官相关 0.93 到 0.96，动态趋势对齐。但营养器官高估约 2 倍，果实完全未发育。

**仍存在的问题。** LAI 严重高估，17.89 vs DSSAT 1.37。缺叶片衰老、SLA 动态变化、叶面积扩展限制。果实卡在 FRUIT_SET 阶段未发育。PAR 修复正确提升光合但缺限制机制。

### 【第16页】修改9：ALFDOT 叶面积扩张 + SENES 叶片衰老机制

**讲解内容：**

## 第三部分：STEP2——机制对齐与 LAI 正反馈修复（第17-28页）

### 【第66页】今日关键经验教训

**讲解内容：**

这一页总结了 7 月 2 日当天的 7 条关键经验教训，这些是整个项目中最有价值的知识沉淀。

1. **TEMPOD/FNSDT 必须用 QDR（二次）CURV 而非线性。** Python 用线性公式加错误的 0.6 因子导致 30 度到 0.4 而非 0.0；修复为 8 点正弦温度加 QDR CURV 平均后，G#AD 改善 14.18 个百分点，GWAD 改善 7.42 个百分点。这是今日最关键的 Bug 修复。

2. **TDAY 必须用 DSSAT PODS.for 定义：(tmax+tmin)/2 + 2.0。** Python 用简单 tavg 导致繁殖期温度因子偏低 20-30%，种子生长率偏低，GWAD 低估 15%。2 度差异在 10-18 度繁殖期影响显著。

3. **SHMAXG 修复不一定有效（需先确认瓶颈）。** SHMAXG 从 0.316 到 0.494 但对 G#AD/GWAD 无效果，因为 max_pods_by_carbon 从未成为瓶颈。修复前需先诊断瓶颈所在。

4. **经验校正与公式正确性需区分。** 当前 7/8 指标达标是经验校正结果，非公式正确。错误间存在相互补偿关系。

5. **DSSAT 采收机制不能直接移植。** Python 早期座果时间晚于 DSSAT，且 Python 同日采收 vs DSSAT 1 天延迟。需先修正 R1 时点。

6. **KCANR 是特殊情况（源代码与运行行为不一致）。** DSSAT 源代码与实际运行行为不一致，不宜按源代码强制修改。保持 KCANR 等于 0.67 是正确选择。

7. **分层修复策略优于全量统一。** 全部公式统一会破坏相互补偿关系。建议优先处理低风险项，避免破坏性改动。
